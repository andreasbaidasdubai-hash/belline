Read this first

The UAE has a problem you need to know about before you spend anything.

Twilio does not sell +971 numbers. VoIP termination in the UAE sits with the licensed operators — Etisalat and du — and the TDRA does not hand that out to international CPaaS providers. So the obvious plan (buy a Dubai number, point it at Belline) is not available.

Two things follow, and they are not the same problem:

  • For a demo you can hand to prospects today — buy a UK or US number. Anyone in the UAE can dial it; outbound international calling is not restricted, only inbound VoIP termination is. It costs the caller international rates, so it reads as a demo line rather than a business line, which for a demo is fine.
  • For a Dubai venue actually using it in production — they keep their Etisalat or du number and forward it. Nobody ports anything. See Part 5, which is the part that answers "how do people install this on their number".

Verify before you buy. Number availability and regulatory rules change. Check Twilio's console for the country you want before committing — and treat every price below as approximate.

Part 0 · Name and website

Get the domain up before anything else.

About an hour, and it is the only part a prospect sees before they decide whether to take your call seriously.

  1. Buy the domain

    Namecheap, Porkbun or Cloudflare Registrar. Buy the .com too if it is affordable, even if you launch on something else — it stops someone else becoming you later.

    A registry says a name is unregistered; it does not promise you can have it. Premium pricing and registry reservations both bite at checkout. Confirm in the cart before you commit to a name.

  2. Build the static site

    npm run site

    Produces a site/ folder: the landing page as index.html plus the plan, market study and this runbook. Four files, no build step, no dependencies.

  3. Publish it

    Drag site/ onto Netlify Drop — live in about ten seconds, free, no account needed to try. Or npx vercel deploy --prod site.

    Then point the domain at it and let the host issue the certificate.

  4. Split the two halves across subdomains

    The website and the app are different things with different hosting needs. Keep them apart from day one: 

    yourdomain.com       → the website        (Netlify / Vercel, static, free)
app.yourdomain.com   → the dashboard      (Railway — needs a live process)

    The app cannot go on Vercel: it holds a websocket open for the length of every call, and a serverless function has no persistent socket.

Part 1 · Keys

Make it speak, locally.

About 20 minutes. At the end of this you can talk to it through your laptop microphone.

  1. Anthropic API key

    console.anthropic.com → API keys → create. Add about $20 of credit.

    This is billed separately from your Claude Code subscription — they are different products on the same account.

  2. Deepgram key

    console.deepgram.com → sign up → API keys. There is free starting credit, which is more than enough to get through testing.

  3. ElevenLabs key

    elevenlabs.io → Profile → API key. The free tier will not do — it lacks the low-latency streaming you need. Starter is enough to test.

    Once this key is set, the Agent page loads every voice on your account, including any you clone, and the "Hear it" button speaks your venue's own greeting.

  4. Put them in .env

    In the belline folder, copy .env.example to .env and fill in the three keys. Then:

    npm run dev

    The startup banner now shows three ticks instead of three dots. Open the test console and press Speak — that is the real pipeline, end to end.

Part 2 · Hosting

Put it somewhere Twilio can reach.

A phone call arrives from the public internet, so the process has to live there. It also has to be a process — the voice bridge holds a websocket open for the length of every call, which is why this cannot go on Vercel. Railway is the least friction; Fly and Render work identically.

  1. Put the code on GitHub

    cd belline
git init
git add -A
git commit -m "Belline: AI voice receptionist"
gh repo create belline --private --source=. --push

    Private. The repo contains your venue configurations and, once running, your guests' phone numbers.

  2. Deploy on Railway

    railway.app → New Project → Deploy from GitHub → pick the repo. It will find the Dockerfile and build.

    Add the same three keys as environment variables, plus PORT=3000.

  3. Attach a volume — do not skip this

    In Railway: Variables → add DATA_DIR=/data, then Settings → Volumes → mount one at /data.

    Without a volume, every deploy wipes the booking file. A venue losing tonight's book because you pushed a change is the one failure they will never forgive.

  4. Note the public URL and set the websocket origin

    Railway gives you something like belline-production.up.railway.app. Add two more variables:

    PUBLIC_WS_ORIGIN=wss://belline-production.up.railway.app
SESSION_SECRET=<40+ random characters>

  5. Claim the owner account — immediately

    Open the URL. Because nobody has signed up yet, you get a create the owner account form. Fill it in now.

    That form is open to whoever loads the page first, and it has to be — there is no account to authenticate against yet. It closes permanently the moment one account exists. Do not deploy and then go to lunch.

    After that, everything is behind a login. Add the rest of your team on the Team page: managers can change how the agent behaves at their venues, floor staff can only read the book and the calls.

Locked out later? Passwords are reset from the server, not by email — npm run user -- reset you@example.com "a new long password" in a Railway shell. Shell access is the root of trust; there is no password reset link to phish.

Part 3 · The demo line

Three numbers a prospect can ring.

One per trade, so a clinic owner hears a clinic rather than a restaurant script or a keypad menu. The webhook already routes an incoming call by the number that was dialled, so this is configuration, not code — and three numbers cost about $3.50 a month in total.

A public number is a spend endpoint. Anyone can dial it, and every minute bills four vendors. Each demo venue is capped at 40 calls a day — refused in the webhook before any vendor connects — with a four-minute maximum call, a disclosure in the opening line, and the previous day's demo bookings cleared so the diary never reads as full. Watch it on the Demo line page in the dashboard.

Part 3b · Buying them

From an empty Twilio account to a ringing phone.

  1. Twilio account

    twilio.com → sign up → upgrade from trial (a trial number plays a warning message before every call, which ruins a demo). Load about $20.

  2. Buy three numbers

    Phone Numbers → Buy a number → United Kingdom → filter for Voice. Roughly $1.15 a month each, no address documentation, live in about a minute. Buy one for restaurants, one for salons, one for clinics.

    Not +971: Twilio does not sell UAE numbers. Anyone in the UAE can dial a UK number normally — outbound international calling is not what the TDRA restricts.

  3. Tell each venue which number is its own

    In the dashboard, open each venue and set its phone number to the matching Twilio number. This is what the routing keys off — get it wrong and a clinic prospect hears the restaurant.

  4. Point all three at the webhook

    Open each number → Voice Configuration → A call comes in → Webhook, HTTP POST:

    https://app.yourdomain.com/api/twilio/voice

    Then add TWILIO_AUTH_TOKEN to your Railway variables — the webhook verifies Twilio's signature, and without that token anyone who guesses the URL can start calls that bill three vendors to you.

  5. Check your work without guessing

    npm run doctor

    It calls every provider with your keys, lists each Twilio number and whether its webhook actually points at Belline, warns you if the account is still on trial, and POSTs to your own webhook from outside to prove Twilio can reach it.

  6. Ring all three, then put them on the website

    Call each one from your phone. Book something, change it, try to catch it out. Then replace the placeholder numbers in the Hear it now section of the landing page, run npm run site, and redeploy.

Part 4 · The venue

Set up a real restaurant or salon.

Everything a venue needs is editable without a deploy. Work through it with them on the phone; it takes about half an hour and it is the part that makes the agent sound like it works there.

  • Tables — every table, its real minimum and maximum covers, and which section it is in. Or, for a salon: every service with its true duration, cleanup time and price, and which staff member can do what.
  • Turn times — how long you actually hold a table by party size. Getting this wrong is how you double-seat.
  • Pacing — the most covers the kitchen will take in any quarter hour. Ask the head chef, not the owner.
  • Hours and last seating — per service, per weekday.
  • House rules — deposits, large-party policy, what it must never promise. These become hard constraints.
  • Common questions — parking, dress code, dietary, payment. In their words, as they would say them aloud.
  • Voice and greeting — pick the voice, preview it saying the venue's own name.
Part 5 · The bit everyone asks about

How a venue puts this on the number they already have.

They never give up their number. No porting, no telling customers to call something new, no changes to their Google listing or their printed menus. They forward it.

Two ways to forward, and you should sell the second one

SettingWhat happensWhen to use it
Unconditional Every call goes straight to Belline. The venue's phone never rings. Venues who want the phone off the floor entirely, or out of hours.
On no-answer / busy The phone rings at the host stand for 15–20 seconds. If nobody picks up, or the line is engaged, it rolls to Belline. Start here, always.

The second one is the whole sales pitch. The venue risks nothing: staff answer exactly as they do today, and the AI only ever picks up calls that would otherwise have gone to voicemail. You are not asking them to replace their team. You are asking them to stop losing the calls they were already losing.

On a mobile line

Most single-site salons run on a mobile. These are standard GSM codes — the venue dials them like a phone number, on the handset itself:

# roll to Belline after 20 seconds of ringing
**61*+441234567890*11*20#

# roll to Belline when the line is engaged
**67*+441234567890#

# check what's currently set
*#61#

# turn it all off again
##002#

Replace the number with your Belline line. Confirm the exact codes with the operator — Etisalat, du, Swisscom and Telekom all support these, but occasionally with their own variations.

On a landline or a PBX

Set in the operator's business portal, or in the PBX if they have one (3CX, Cisco, Yealink, most cloud systems). If the venue has an IT company, this is a five-minute job for them. If they do not, the operator's business support line will do it.

Forwarding a UAE landline internationally costs the venue money — every forwarded call becomes an outbound international call on their bill. Check the per-minute rate with Etisalat or du before you promise a Dubai venue this is free. It is the strongest single reason to pursue a UAE-licensed SIP provider once you have paying customers.

Part 6 · By country

UAE, Switzerland, Germany, Austria.

CountryNumber on TwilioWhat it needsRealistic lead time
UAE +971 Not available A UAE-licensed operator or SIP provider. TDRA restricts VoIP termination. Weeks, and possibly a dead end. Use forwarding meanwhile.
Switzerland +41 Available A Swiss address on the regulatory bundle. Baidas & Baidas AG covers this. A few days for approval.
Germany +49 Available A German address — and for a geographic number, one in that area code's region. Strictest of the three. Up to a couple of weeks.
Austria +43 Available An Austrian address on the bundle. A few days to a week.

For DACH the practical order is: get the Swiss number first, since you already have the company there, and use forwarding for German and Austrian venues until volume justifies local numbers. Forwarding works identically in all three and costs the venue almost nothing within the EU.

Two things to sort before a European venue goes live

  • Say it's an AI. The EU AI Act requires people to be told they are talking to an AI system. Put it in the greeting — "you're speaking to our automated assistant" — which is a one-line change on the Agent page. Do it for Switzerland too; it is good practice regardless of whether Swiss law compels it.
  • Transcripts are personal data. Belline stores transcripts, not audio, but a transcript with a caller's name and number is personal data under GDPR — and under the UAE's PDPL. Germany in particular treats recording a call without consent as a criminal matter, so do not add audio recording without taking advice first.

None of this is legal advice — get it checked before a paying venue is live. It is cheap to handle now and expensive to retrofit.

Part 8 · Honest gaps

What still has to exist before you can charge someone.

None of these block a demo. All of them block an invoice.

  • A real database. The booking file works for one server. Two venues on one deploy is fine; two servers is not — and the login throttle is per-server memory, so it weakens the moment you scale out.
  • Password reset by email. Today an owner resets a password from the server shell. Fine for your own team, awkward once a venue manager locks themselves out on a Saturday night.
  • Two-factor. A single password now guards every guest phone number you hold. Worth adding before you have many.
  • SMS confirmation. The booking reference is only ever spoken aloud. Callers write it down wrong.
  • A PMS integration. Until Belline writes into SevenRooms or Fresha, it is a second book — which most established venues will not accept for long. Fresha first; salon penetration is highest there.
  • Someone watching the calls. For the first few weeks at any venue, read every transcript the morning after. That is how you find the policy you forgot to write down.
